    VSYS26T2-14: Relay + P2P with NAT hole-punching (replaces direct-only P2P)¶

    Context¶

    Today, dsync is purely peer-to-peer over TCP+TLS with mDNS-based discovery: every device must run a server, peers must be on the same LAN (or have ports forwarded). Cross-network sync is effectively impossible without manual IP and firewall work.

    The goal is WAN-friendly sync without manual network configuration. Approach: introduce relay servers as pure rendezvous points that observe each connected peer's public UDP endpoint and broker NAT hole-punching, after which two peers form a direct QUIC connection for the actual file transfer. Relays never see file bytes. The same dsync binary can run as a relay. mDNS and the legacy direct-connection commands are removed for a clean break.

    This is a breaking change: transport switches from TCP+TLS to UDP+QUIC, and discovery moves from mDNS to relay-based registration.

    Architecture overview¶

                    ┌──────────────────────┐
                │   relay (dsync       │
                │   relay serve)       │
                └──────────┬───────────┘
        control channel    │   control channel
        (QUIC, app auth)   │   (QUIC, app auth)
                ┌──────────┴───────────┐
                │                      │
        ┌───────▼─────┐         ┌──────▼──────┐
        │  peer A     │         │  peer B     │
        │ (dialer)    │◄═══════►│ (listener)  │
        └─────────────┘  direct └─────────────┘
                        QUIC stream after
                        UDP hole-punch
    • Control channel: long-lived QUIC connection peer↔relay, established by dsync relay connect <id>. Holds NAT mapping open via app-layer CONTROL_PING.
    • Signaling: dsync sync run_backup talks to the local relay connect process over a Unix-domain socket (POSIX) / loopback TCP + bearer token (Windows). The control-channel process sends CONNECT_REQUEST to the relay; relay forwards endpoint info to both peers via PUNCH_INFO.
    • Hole-punch: both peers reuse their control-channel UDP socket to send a burst of UDP datagrams toward the other's relay-observed endpoint (preserves the NAT mapping). One side (assigned by relay as dialer) then initiates QUIC INITIAL; the other (listener) accepts.
    • Auth: keep existing SPKI + RSA-PSS signature over TLS channel binding from dsync/network/node.py:179-196; reimplemented over aioquic via export_keying_material post-handshake.
    • Same-relay invariant: enforced at config-load via a new relay_id FK on TrustedDevice — both peers' device entries must point at the same relay id.

    Protocol messages (control channel)¶

    Type Direction Payload
    AUTH peer → relay existing 294B SPKI + 256B sig (over channel binding)
    REGISTER_ACK relay → peer relay's observed (ip, port) of peer
    CONTROL_PING bidirectional empty, every 15s — NAT keepalive
    CONNECT_REQUEST peer → relay target_fingerprint
    PUNCH_INFO relay → peer peer_endpoint, peer_fingerprint, role: dialer|listener
    ERROR relay → peer reason (peer-unknown, peer-offline, untrusted)

    Reuses the MsgType enum pattern from dsync/network/p2p_core.py:20-35; drops the 5-byte length-prefix in favor of one QUIC stream per logical message.

    Implementation order¶

    1. Config & state expansion — add dsync/config/relay.py, relays.yaml, TrustedDevice.relay_id (with FK validation in config_dir.py), wire into AppState. Add relay add/list/mod/rm. Update dsync-config/devices.yaml examples. Pure additive; existing flows untouched.
    2. QUIC primitives + channel binding — add aioquic dep, write quic_core.py with get_quic_channel_binding. Unit test: two in-process QuicConnections exchange a payload and both compute the same 32-byte binding using export_keying_material. Pin aioquic version.
    3. Relay protocol + server — relay_protocol.py, relay_server.py, dsync relay serve command. Stub relay_client.py that registers and exits. Loopback test: server logs REGISTER_ACK and observes the right ephemeral port. Assert relay sees zero FILE_* frames in any test from PR 5+.
    4. Hole-punch + BYO-socket QUIC — hole_punch.py + the aioquic DatagramProtocol wrapper that lets a QuicConnection reuse an already-bound UDP socket pointed at a specific peer endpoint. Loopback test exercises burst-send, role assignment (dialer/listener via relay), and retry-once.
    5. PeerSession over QUIC — port AUTH frame + BackupSession + ConfigExchange + file_transfer.send/recv_file to QUIC streams. Direct (non-relayed) QUIC integration test on loopback between two PeerSession instances. Existing BackupSession direction enforcement at backup_direction.py:56-116 should pass through unchanged.
    6. IPC + run_backup rewrite — local_ipc.py; relay connect hosts the daemon; rewrite sync run_backup to use it. End-to-end test on loopback through a real relay process: relay serve + 2× relay connect + sync run_backup. This is the first PR where the full new flow exists.
    7. Legacy removal — delete discovery.py, identity.py, _start_peer.py, p2p_core.py, node.py, cli/commands/peer/*, cli/commands/sync/start.py. Remove pyp2p and zeroconf from pyproject.toml. grep -r 'zeroconf\|PeerMapStore\|peer_announce' dsync/ must come back clean.
    8. Hardening + docs — app-layer CONTROL_PING every 15s on the relay client; auto-reconnect with exponential backoff on transient drops; friendly typer errors for relay-unreachable, relay_id-mismatch, punch-failed, peer-not-registered. ADR-002, README testing section, conventions update, research doc.

    Verification¶

    Done in this order — each level catches different failure modes.

    • Unit (PR 2): two QuicConnections in one process produce matching channel-binding bytes.
    • Loopback integration (PR 3–6): spawn relay serve, two relay connect, run sync run_backup. Assert file lands in received-files/, SHA-256 matches, BackupSession direction enforcement still raises on a wrong-way send, relay process logs show zero FILE_* frames.
    • Simulated NAT (PR 4 onwards, in CI): Docker Compose, two containers behind iptables -t nat -A POSTROUTING -j MASQUERADE, relay on a third "internet" container. Run the full flow. This is the load-bearing NAT-traversal test — LAN tests prove nothing about real hole-punching.
    • Cross-WAN smoke (manual): once two real machines on different networks are available, run the full flow and capture timing + success rate. Document expected failures on symmetric NATs.
    • Lint/type/security: uv run pre-commit run --all-files (Ruff, mypy strict, Bandit) must pass on every PR.

    Risks & mitigations¶

    Risk Mitigation
    aioquic's TLS keying-material exporter is private API in some versions Pin aioquic; isolate access in quic_core.get_quic_channel_binding so a future swap is one function. Gate PR 2 on confirming public API exists.
    Symmetric NATs break hole-punching Documented limitation. Add relay-fallback (TURN-style) explicitly as out-of-scope future work in ADR-002.
    Windows UDS unavailability local_ipc.py branches: UDS on POSIX, loopback TCP + bearer token on Windows. Same LocalControlClient interface.
    LAN-only testing fakes success CI uses Docker+iptables MASQUERADE (PR 4 onwards). Manual cross-WAN smoke before declaring "done".
    Relay metadata exposure (relay sees who talks to whom and when) Acknowledged in ADR-002. File content never traverses relay.
    Breaking change leaves users without a migration This is a course PoC, not a released product — clean break is acceptable. README rewrite covers new flow.

    Out of scope for this plan¶

    • Cross-relay federation (peers on different relays).
    • TURN-style relay fallback when hole-punching fails.
    • Daemonized/backgrounded relay connect — kept foreground; revisit after this lands.
    • Key rotation for relay or peer keys.
